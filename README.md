# 통조림

통조림은 작가의 지시에 따라 소설 원고를 한 장면 정도 이어 쓰는 한국어 집필 도구입니다. 내 컴퓨터에서 서버를 실행하고 데스크톱 브라우저로 사용합니다. AI 생성에는 OpenRouter를 사용합니다.

## 시작하기

AI 기능을 사용하려면 `package.json`과 같은 폴더에 `.env` 파일을 만들고 OpenRouter API 키를 설정합니다.

```dotenv
OPENROUTER_API_KEY=여기에_발급받은_키
```

서버 환경 변수로도 설정할 수 있습니다. 기존 변수 이름인 `OPENROUTER_API`도 지원합니다. API 키는 서버에서만 읽습니다.

### Docker Desktop에서 실행

1. Docker Desktop을 Linux 컨테이너 모드로 실행합니다. 이미 `npm start`로 통조림을 켜 두었다면 먼저 종료합니다.
2. 저장소 루트의 `docker-update.cmd`를 더블클릭합니다. 현재 폴더의 코드로 이미지를 빌드하고 서버가 응답할 때까지 기다립니다.
3. 이전에 사용하던 브라우저에서 [집필실](http://127.0.0.1:4173)이나 [모델 설정](http://127.0.0.1:4173/settings)을 엽니다.

코드나 `.env`를 바꾼 뒤에는 `docker-update.cmd`를 다시 실행합니다. 같은 버전을 다시 시작하거나 일시적으로 중지하려면 Docker Desktop의 **Containers**에서 `tongjorim` 프로젝트의 앱 컨테이너를 선택해 **Restart** 또는 **Stop**을 누릅니다.

컨테이너는 저장소의 `data/tongjorim.sqlite`를 사용하므로 기존 원고와 설정을 그대로 열 수 있습니다. 컨테이너를 다시 만들어도 데이터는 `data/`에 남습니다.

### Node.js로 직접 실행

Node.js 22.13 이상에서 저장소 루트의 `npm start`로 실행합니다. Windows PowerShell에서 `npm.ps1` 실행이 차단되면 `npm.cmd start`를 사용합니다. 종료하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

두 실행 방식 모두 기본 주소는 `http://127.0.0.1:4173`입니다. 다른 앱이 기본 포트를 쓰고 있다면 `.env`에 `PORT=4174`를 추가하고 서버를 다시 실행한 뒤 해당 포트로 접속합니다.

### OpenRouter 사용량과 크레딧

**설정 → OpenRouter 사용량**에서 집필용 키의 사용액과 남은 지출 한도를 확인할 수 있습니다. 계정 크레딧 잔액도 보려면 [OpenRouter 관리 키 발급 화면](https://openrouter.ai/settings/management-keys)에서 발급한 관리 키를 `.env`에 추가하고 서버를 다시 시작합니다.

```dotenv
OPENROUTER_MANAGE=여기에_발급받은_관리_키
```

## 집필하기

1. **설정**에서 **이어쓰기 모델**을 선택합니다.
2. 집필실에서 원고를 입력하고 **작가의 노트**에 다음 장면의 지시를 적은 뒤 **이어서 쓰기**를 누릅니다.
3. 생성이 끝나면 원고 마지막 문단 아래에 초안이 표시됩니다. **수정 지시**를 입력하고 **다시 써줘**를 누르면 현재 초안을 바탕으로 새 버전을 만듭니다.
4. 사이드바 **수정 내역**에서 작가의 노트와 수정 지시를 확인하고 버전을 선택합니다. **원고 끝에 붙이기**를 누르면 보고 있던 버전이 원고에 추가되고 장면과 버전 내역이 저장됩니다.
5. 원고를 입력하면 현재 장면에 속합니다. 줄 번호 옆 **+ 새 장면**으로 두 장면 사이 또는 원고 끝에 빈 장면을 만듭니다. 기존 장면은 원고에 커서를 놓고 사이드바 **장면 → 장면 나누기**로 나눕니다. **장면 다시 쓰기**에서 수정한 버전은 **이 장면 교체**로 반영합니다.

줄거리는 산문으로 작성하며 이어쓰기마다 전문을 보냅니다. 인물과 세계관 설정은 로어북 카드로 관리합니다. 기존 인물·세계관 메모는 작품을 열거나 백업을 복원하면 카드로 옮겨집니다. **요청 미리보기**에서 포함된 로어북 카드를 확인하고 빠진 카드를 이번 요청에 추가할 수 있습니다.

메인 **로어북**에서 카드를 작성하고, 카드마다 AI와 대화하며 초안이나 수정안을 편집란에 반영해 저장할 수 있습니다. 사이드바 **로어북**에서는 분류별 카드의 **항상 포함**과 **이번 요청에 포함**을 설정합니다.

선택한 문단을 퇴고하거나 줄거리 작성에 AI 도우미를 사용할 수 있습니다. **의미 검색**을 켜면 검색어와 과거 원고 문단이 OpenRouter로 전송되며 임베딩 비용이 발생할 수 있습니다.

## 저장과 백업

원고, 작품 메모와 설정은 서버의 `data/tongjorim.sqlite`에 자동 저장됩니다. 서버에 첫 작업공간을 저장할 때 현재 브라우저에 보관된 기존 작품을 가져옵니다. 기존 작품이 들어 있는 브라우저에서 먼저 접속해 **서버에 저장됨**을 확인하세요. 다른 작업 환경의 작품은 **작품 파일 → JSON 백업**에서 저장한 뒤 **새 작품으로 복원**으로 불러올 수 있습니다. 원고만 필요하면 **TXT 내보내기**를 사용합니다.

서버 저장이 충돌하면 **작업공간 충돌 복구**에서 브라우저에 있는 작품 전체를 JSON으로 백업하고, 그 파일을 선택해 서버 사본을 열 수 있습니다. 충돌한 작품들을 다시 열려면 **작품 파일 → 새 작품으로 복원**에서 같은 파일을 선택하세요.

모델 생성 요청과 응답은 같은 SQLite 파일의 `model_requests`에 작품 ID와 함께 기록됩니다. `request`에는 전송한 요청 본문, `response.text`에는 모델 답변 원문, `response.raw`에는 OpenRouter의 원본 응답이 남습니다. 기록에는 원고와 작품 메모가 포함될 수 있습니다.

작품 삭제가 서버에 저장되면 해당 작품은 현재 작업공간과 직전 스냅샷에서 제거되며, 작품 ID에 연결된 모델 요청·응답 기록도 삭제됩니다.

## 테스트

```sh
npm test
```

화면이나 생성 흐름을 확인하려면 `npm run qa:server`를 실행한 뒤 [QA 집필실](http://127.0.0.1:4184)을 엽니다. 설정에서 이어쓰기 모델로 `qa/write`를 선택하면 실제 API 키 없이 샘플 원고로 이어쓰기를 확인할 수 있습니다. 검색을 점검하려면 모의 서버가 실행 중인 상태에서 별도 터미널로 `npm run qa:retrieval -- 4184`를 실행합니다.

모의 서버에서 필터 중단, 모델 오류, 출력 한도 도달과 정상 종료를 검증하려면 `npm run qa:stream -- 4184`를 실행합니다.

개발 시 저장소의 [작업 지침](AGENTS.md)을 참고하세요.
